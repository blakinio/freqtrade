# Residual PyTorch bounded M1 execution

## Decision

P3 is a one-shot historical-development comparison of three frozen FreqAI regressors:

- `M1LightGBMRegressor`, instrumenting the canonical `LightGBMRegressor`;
- `M1SeededPyTorchMLPRegressor`, instrumenting `SeededPyTorchMLPRegressor`;
- `M1ResidualPyTorchRegressor`, instrumenting `ResidualPyTorchRegressor`.

The comparison is descriptive research evidence only. It defines no winner, selection gate, promotion path or profitability claim.

## Frozen strategy and data contract

All tracks use `AiFrozenCandidateStrategy` with:

- target `&-future_return`;
- numerator offsets `t+1` through `t+12`;
- entry threshold `0.006`;
- exit threshold `-0.009`;
- identical expanded feature parameters and chronological `80/20` split;
- no liquidation-derived feature.

Only model identity and prospectively fixed model-specific parameters differ. LightGBM uses the previous simple-tree identity with seed `42`; the seeded MLP preserves its one-layer 64-unit, three-epoch baseline; the residual MLP preserves the M1 architecture and eight-epoch runtime defaults.

## Mandatory matrix audit

`ResidualPyTorchM1DataAuditRegressor` runs before all three comparators. It does not optimize a predictor. It uses a zero regressor only to allow the normal FreqAI feature-expansion path to complete.

For each pair it records:

- raw FreqAI-expanded feature names, count and stable name hash;
- per-column finite, NaN, infinity, quantile and IQR-outlier statistics;
- target distribution and exact trailing-null geometry;
- eligible row count before the split;
- transformed train/test dimensions and finite checks.

Execution fails before comparator fitting unless both pair reports exist, feature identity is equal across pairs, the frozen target has exactly 12 trailing null rows, all transformed matrices are finite and at least 1,000 eligible rows remain per pair.

## Model evidence

The wrapper mixin adds evidence only; it does not change the underlying fit or prediction algorithms. Each model records:

- exact config, manifest, strategy, wrapper and request bindings;
- model files and FreqAI model directory;
- train/test row and feature counts;
- LightGBM evaluation history or PyTorch train/test scalar-loss history;
- dated prediction rows with target, prediction, `do_predict` and DI value;
- MAE, Smooth L1 loss, directional accuracy, Spearman rank IC and prediction distributions;
- normal Freqtrade backtest archive and trading metrics.

Metrics include only rows inside the March-April development window with finite target and prediction and `do_predict == 1`.

## Two-PR execution protocol

The infrastructure workflow triggers only when a later pull request is opened against `develop` and adds exactly:

```text
ai_platform/experimental_model_research/run-requests/residual-pytorch-bounded-m1-execution-v1.json
```

The request must exactly match the canonical payload generated by:

```bash
python -m ai_platform.scripts.residual_pytorch_bounded_m1_run_request --print-canonical
```

Before dependency installation or market-data access, the workflow verifies the exact one-file diff and active task checkpoint. It then uses a dedicated pre-May Kraken cache namespace with no fallback restore keys. The trigger PR is evidence plumbing and must be closed without merge after terminal artifact collection.
